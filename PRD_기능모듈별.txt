 작성일: 2026-08-27
 버전: v1.0 (데모 기획 단계)

본 문서는 동일 프로젝트를 "개발 단계"가 아닌 "제품을 이루는 기능
모듈" 기준으로 재구성한 것이다. 각 모듈은 목적 / 입력·출력 /
상세 기능 / 데모 포함 여부 / 오픈 이슈로 구성된다.


====================================================================
모듈 1. 온보딩 & 취향 설문
====================================================================

[목적]
매 여행 시작 시점마다 사용자의 취향을 가볍게 파악해 이후 모든
추천(지역 추천, 여행지 추천)에 반영한다.

[입력/출력]
- 입력: 사용자의 설문 응답(탭 선택)
- 출력: 취향 객체 { tempo, themes[], companion, budget } - 세션 상태로
  전달

[상세 기능]
- 여행 템포: 느긋 / 보통 / 빡빡 (단일 선택)
- 선호 테마: 자연 / 맛집 / 카페·감성 / 액티비티 / 역사문화 (다중 선택)
- 동행 형태: 혼자 / 커플 / 친구 / 가족 (단일 선택)
- 예산대: 저가 / 중가 / 고가 (단일 선택)
- 로그인 여부와 무관하게 동일하게 노출(로그인 사용자도 매번 새로
  묻거나, 최종본에서는 이전 응답을 기본값으로 제시하는 것도 고려 가능
  - 데모는 매번 신규 입력)

[데모 포함 여부] 포함 (필수)

[오픈 이슈]
- 없음 (사용자가 항목을 그대로 승인함)


====================================================================
모듈 2. 숙소 입력
====================================================================

[목적]
사용자가 이미 정해둔 숙소가 있다면 그 위치를 이후 여행지 추천에
반영한다.

[입력/출력]
- 입력: 주소 텍스트 또는 지도 핀 찍기
- 출력: 숙소 좌표 { lat, lng, address } | null

[상세 기능]
- "숙소가 정해져 있나요?" 질문에 예/아니오
- 예 -> 주소 검색창(Kakao 주소 검색 API) 또는 지도에서 직접 핀 찍기
- 아니오 -> 이후 플로우에서 숙소 관련 로직 모두 비활성(숙소 없이도
  전체 플로우 정상 동작)

[데모 포함 여부] 포함 (A안: 사용자 직접 입력만)

[오픈 이슈]
- 없음. 단, B안(앱이 숙소를 추천 + 예약 대리)은 별도 모듈로 향후
  추가 예정이며 이번 범위 아님(모듈 9 참고)

모듈 3. 다트 던지기 & 지역 추천
====================================================================

[목적]
여행지를 처음부터 검색하게 하지 않고, 무작위성을 통해 "우연한
발견"의 경험을 제공하면서도 결과가 실제로 갈 만한 곳이 되도록
POI 밀도 기반으로 필터링한다.

[입력/출력]
- 입력: 서비스 커버 범위(데모: 다트는 경기·서울, 직접 고르기는 전국),
  여행 범위 단위(광역/기초/읍면동), 사용자 거리가중치 설정값
- 출력: 지역 후보 리스트(최소 1개, 최대 3개) { name, lat, lng,
  score }

[상세 기능]
- 지도 위에서 다트가 무작위 좌표에 꽂히는 애니메이션 연출
- 다트 좌표 반경 내 POI(관광명소/카페/맛집/문화시설) 밀도를 Kakao
  Local API로 계산
- 후보 지역 점수 = POI밀도 x (1 + 사용자설정값 x 거리가중치함수)
- 사용자가 슬라이더로 거리 민감도(사용자설정값)를 조절하면 후보
  리스트가 즉시 재정렬
- 역지오코딩으로 좌표를 "대성리", "가평", "청평" 같은 읽을 수 있는
  지역명으로 변환해 카드 형태로 제시
- 지역 선정 방식은 둘이다. 다트 던지기(무작위)와 직접 고르기(지도
  클릭 또는 지역명 검색)
- 여행 범위 단위를 광역자치단체 / 기초자치단체 / 읍면동 중에서 고른다.
  기본은 기초자치단체이며, 단위에 따라 표본 반경과 POI 집계 반경이
  함께 바뀐다
- 현재 위치에서 각 후보까지의 거리 안내는 데모에 넣지 않는다.
  Geolocation 권한과 실기기가 필요해 실기기 단계에서 적용한다
- 사용자가 카드 중 하나를 선택하면 다음 모듈(모듈 4)로 진행

[데모 포함 여부] 포함 (핵심 기능)

[오픈 이슈]
- 거리가중치함수의 구체적 형태(역수/지수감쇠 등)와 계수는 실제 개발
  중 데이터 확인 후 튜닝 필요
- 다트가 바다/접경지역에 떨어질 경우: 후보가 비거나 POI가 전부 0이면
  자동으로 다시 던진다(해결)
- 범위 단위별 표본·POI 반경도 같은 튜닝 대상. 광역 단위는 표본이
  바다·산에 떨어지는 경우가 있어 대표 좌표 산정 방식 재검토 필요

모듈 4. 여행지(미션) 추천 엔진
====================================================================

[목적]
전체 코스를 한 번에 보여주지 않고, 현재 상황(위치·이력·취향·숙소)에
맞춰 매번 1~2곳만 추천해 서프라이즈를 유지하는 이 앱의 핵심 두뇌.
"첫 여행지 추천"과 "다음 여행지 추천"은 입력값만 다를 뿐 동일한
엔진을 공유한다.

[입력/출력]
- 입력: 현재 위치, 선택된 지역, 취향 객체, 미션 이력(카테고리 포함),
  숙소 좌표(있는 경우, 향후 방문 예정이면 방향성 반영)
- 출력: 추천 장소 1~2건 { name, lat, lng, category, reason }

[상세 기능]
- Kakao Local API로 현재 위치 반경 내 카테고리별 후보 장소 조회
- 숙소가 있고 아직 들르지 않았다면 숙소 방향 후보를 일부 포함해
  동선을 자연스럽게 유도
- 이미 완료/스킵한 장소는 후보에서 제외
- 후보 목록 + 취향 + 이력을 프롬프트로 구성해 OpenRouter 경유 LLM에
  전달, 1~2곳 선정과 함께 추천 이유 문장 생성
- 추천 카드에 예상 이동 거리/시간 표시

[데모 포함 여부] 포함 (핵심 기능)

[오픈 이슈]
- 이동수단(도보/대중교통/자차) 가정에 따라 반경 설정이 달라짐 - 확정
  필요


====================================================================
모듈 5. 미션 진행 & 사진 인증
====================================================================

[목적]
사용자가 실제로 그 장소에 도착했는지 검증하고, 검증된 순간 다음
미션이 열리도록 게이미피케이션 루프를 완성한다.

[입력/출력]
- 입력: 카메라로 촬영한 사진
- 출력: 인증 성공/실패, 인증 방식(exif/geolocation/manual)

[상세 기능]
- 카메라 즉석 촬영만 허용(갤러리 업로드 비활성화)
- 1차 검증: 사진 EXIF GPS 메타데이터와 목적지 좌표 간 거리 계산,
  임계값 이내면 통과
- 2차 폴백: EXIF 위치 정보가 없으면 촬영 시점에 브라우저
  Geolocation API로 위치를 별도 요청해 동일 방식으로 검증
- 두 방법 모두 불가할 경우 수동 확인(사용자 체크) - 데모 한정 임시
  허용
- 인증 성공 시 사진과 메타데이터를 미션 이력에 저장

[데모 포함 여부] 포함 (핵심 기능)

[오픈 이슈]
- 인증 임계 거리(예: 200m) 값은 실기기 GPS 오차 테스트 후 확정
- iOS Safari의 EXIF GPS 제공 여부 사전 검증 필요(안 되면 전량
  Geolocation 폴백으로 갈 가능성 있음)

모듈 6. 스킵 / 대체 추천
====================================================================

[목적]
추천된 장소가 폐업했거나 접근 불가능한 경우 여행이 끊기지 않도록
즉시 대체 장소를 제공한다.

[입력/출력]
- 입력: "여기 갈 수 없어요" 액션
- 출력: 동일 지역 내 대체 추천 장소 1건

[상세 기능]
- 미션 카드에 스킵 버튼 배치
- 스킵 시 모듈 4(추천 엔진)를 동일 조건으로 재호출하되, 스킵된
  장소는 후보에서 제외하고 즉시 대체안 1곳 제시

[데모 포함 여부] 포함

[오픈 이슈]
- 없음

모듈 7. 미션 이력 관리 (세션 상태)
====================================================================

[목적]
익명 사용자의 현재 여행 세션 동안의 모든 상태(취향, 숙소, 다트
결과, 지금까지의 미션들)를 유지해 새로고침에도 끊기지 않게 하고,
추천 엔진(모듈 4)이 참고할 데이터를 제공한다.

[입력/출력]
- 입력: 각 모듈에서 발생하는 상태 변화
- 출력: 세션 전체 상태 객체

[상세 기능]
- localStorage에 세션 ID, 취향, 숙소 좌표, 다트 좌표, 선택 지역,
  미션 리스트(장소/좌표/카테고리/상태/시간)를 저장
- 사진 원본은 IndexedDB에 별도 저장(localStorage 용량 한계 고려)
- 브라우저 종료/기기 변경 시 이력 초기화(익명 사용자는 서버 DB에
  저장하지 않음 - 사용자 확정 사항)
- 데이터 모델은 향후 서버 DB(TripSession, Mission 테이블)로 그대로
  이관 가능하도록 필드명을 동일하게 설계

[데모 포함 여부] 포함 (인프라성 모듈, 필수)

[오픈 이슈]
- 없음

모듈 8. 여행 기록 정리 & 공유용 편집
====================================================================

[목적]
여행 종료 후 그동안의 미션 사진들을 보기 좋게 정리해, 사용자가
직접 SNS 등에 올리기 편하도록 만든다. (SNS API 직접 연동은 하지
않음 - 이미지 생성/다운로드까지가 범위)

[입력/출력]
- 입력: 세션에 쌓인 미션 이력(사진 포함)
- 출력: 편집된 요약 이미지(들) - 다운로드 가능한 형태

[상세 기능]
- 미션 순서대로 타임라인/그리드 뷰 제공
- 사진 위에 장소명, 방문 순서, 날짜 등 텍스트 오버레이 편집 기능
- 완성된 이미지를 기기에 저장(다운로드) - 이후 SNS 게시는 사용자가
  직접 수행

[데모 포함 여부] 포함 (차별화 핵심 요소로 사용자가 명시적으로 포함
요청)

[오픈 이슈]
- 없음

모듈 9. (향후 확장) 로그인 / 계정
====================================================================

[목적]
기기를 넘나들며 취향 데이터를 누적하고 개인화 추천을 고도화한다.

[데모 포함 여부] 미포함 (데모는 완전 익명, 로그인 기능 자체를
구현하지 않음)

[비고]
최종본에서는 소셜 로그인(카카오 등)을 통해 모듈 7의 세션 데이터를
서버 DB의 사용자 계정에 귀속시키는 방향으로 확장 예정


====================================================================
모듈 10. (향후 확장) 숙소 추천 & 예약 대리
====================================================================

[목적]
현재는 사용자가 숙소를 직접 입력(모듈 2, A안)하지만, 향후에는 다트로
정해진 지역 안에서 앱이 직접 숙소를 추천하고 예약까지 대행해
수익모델로 연결한다(B안).

[데모 포함 여부] 미포함

[비고]
B안 확장 시 숙소 가격/예약 링크 등 외부 예약 플랫폼 연동이 필요해
범위가 커짐 - 별도 PRD로 분리 검토 권장
